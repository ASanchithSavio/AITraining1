# Video Games training log

## 2026-08-04 - prototype alias to maintenance control to schematic-pin candidate

### Research decisions

1. Began with a historical arcade hardware family because fixed manufacturer drawings provide stable, atomic terminal facts.
2. Rejected a clock-correction candidate after shortcut searches found a recent repair page that printed the decisive chip location. The older maintenance article also indexed both corrected component values, so the apparent obscurity did not survive post-identification collapse.
3. Kept the archival prototype-title bridge but changed the downstream mechanism completely.
4. Used a contemporary maintenance warning to select one hidden option-switch function without putting the switch number, board coordinate, or data bit in the prompt.
5. Carried the selected switch through a buffer on one schematic block, then carried the resulting data-bus label into the main-processor block on a separate sheet region.
6. Visually inspected the option-switch block and processor block at high resolution. The buffer input pin, buffer output pin, and processor pin are three distinct integers, giving source-grounded confusers.
7. Ran exact and natural shortcut searches using the prototype alias, maintenance symptom, switch vocabulary, bus vocabulary, and likely processor-pin phrasing. Search results exposed the game and source documents but not the complete switch-to-bus-to-processor join.
8. Rewrote the prompt as one factual question. It states only the archival identity clue and the maintenance symptom; it does not name the intermediate publication, schematic package, sheet numbers, switch coordinate, bus line, or answer.
9. Confirmed that the evidence path uses human-readable HTML and PDFs only. No JSON, YAML, flat-file search, Ctrl+F terminal method, calculation, or emulator output is required.

### Status

The candidate is ready for one fresh user-run target-model test. The agent did not query the target model and did not submit a platform form. Exact wording, answer, source URLs, page coordinates, and shortcut queries remain in ignored local notes.

### Reusable lessons

- A service note is useful only when it selects a control or component that must still be carried through a separate drawing.
- Indexed component corrections are weak terminal facts even when they appear in an obscure trade journal.
- A visually traced signal can create fair confusers when the input pin, output pin, bus label, and destination pin are all separately printed.
- A prototype title should identify the released game without becoming the entire difficulty mechanism.
- Search for modern repair logs before promotion; community repair pages often collapse an otherwise strong historical schematic prompt.
- Two visual decisions within one schematic package can be substantive, but source independence must come from the upstream archive and maintenance record rather than from counting sheets as separate sources.
